- Networking Foundations
	- Amazon VPC
		- AWS 클라우드 안에 사용자가 원하는 형태로 구성하는 가상 네트워크 환경을 만들거나 제어하도록 하는 기술
		- 필요한 이유
			- 클라우드 환경에서도 내부 네트워크를 직접 설계하고 통제하기 위해
			- 보안 구조 설계를 위해
			- 온프레미스와 AWS 를 하나의 네트워크처럼 설정하기 위해
		- VPC 에서 설정할 수 있는 것
			- IP 주소 범위 설정
			- 서브넷 설정
				- 퍼블릭 / 프라이빗 서브넷
			- 라우팅 테이블 설정
				- 트래픽 경로 설정
			- 게이트웨이 설정
				- IGW(Internet Gateway)
					- 인터넷 연결
				- NAT Gateway
					- 프라이빗 서브넷에서 인터넷 아웃바운드만 허용
				- VGW(VPN Gateway)
					- 온프레미스 <-> AWS VPN 연결
				- Transit Gateway
					- 여러 VPC 또는 온프레미스 네트워크를 중앙에서 연결
			- 보안 기능 설정
				- Security Group(보안 그룹)
					- 인스턴스 단위 방화벽
					- 상태 저장
					- 포트포워딩
				- Network ACL(NACL)
					- 서브넷 단위 방화벽
					- 상태 비저장
					- 서브넷 포트포워딩
	- AWS Transit Gateway(AWS TGW)
		- 여러 Amazon VPC, 온프레미스 네트워크, 원격 지사를 단일 중앙 허브에서 연결 관리하는 네트워크 라우팅 서비스
		- 작동 방식
			- 모든 VPC는 Transit Gateway에 연결
			- 새 VPC가 추가되면 TGW에 Attach만 하면 자동으로 연결
			- 라우팅 정책은 TGW 라우팅 테이블에서 중앙 관리
	- AWS PrivateLink
		- 퍼블릭 인터넷을 거치지 않고, AWS 내부 네트워크(Amazon Private Network) 안에서만 VPC와 서비스간 통신이 가능하도록 하는 기술
			=> 인터넷 없이 AWS 내부망으로 서비스에 접속하는 보안 전용 통신 방식
		- 핵심 개념
			- Endpoint Service(서비스 제공자)
				- 서비스를 PrivateLink로 제공하고 싶은 쪽
				- NLB(Network Load Balancer) 뒤에 Endpoint Service를 생성
			- VPC Endpoint(Interface Endpoint, 서비스 받는자)
				- 서비스를 사용하고 싶은 쪽
				- 자신의 VPC에 Interface Endpoint(ENI)를 생성하여 내부 ip로 서비스에 접근
		- 작동방식
			- 서비스 제공자는 NLB 뒤에서 Endpoint Service를 개방
			- 서비스 사용자 VPC는 Interface Endpoint 를 생성
			- Interface Endpoint 는 자신의 VPC 안에 생성되는 ENI
			- VPC 내부 IP를 가지고 있음
			- 사용자 내부 IP로 접근하며 트래픽은 AWS 내부망을 따라가므로 인터넷으로 나가지 않음
		- 장점
			- 인터넷 노출을 제거해 보안 강화
			- 네트워크 분리됨 보장
			- 크로스 계정/크로스 VPC연결 간소화
			- 온프레미스에서도 사용이 가능
		- 사용하는 환경
			- 외부 SaaS 서비스가 제공하는 AWS PrivateLink를 통해 연결
			- 다른 AWS 게정에 있는 내부 서비스에 접근
			- 서비스 통신을 인터넷에서 완전히 차단할 때
			- 금융권 류에서 사용 시
- Global&Hybrid Connectivity
	- AWS Direct Connect
		- 온프레미스와 AWS를 전용선으로 직접 연결하는 서비스
		- 사용 시 효과
			- 보안 강화
			- 낮고 안정적인 지연
			- 대역폭 증가
			- 공공기관 및 대기업에서 필수
	- AWS Direct Connect SiteLink
		- AWS Direct Connect가 내 온프레미스와 AWS가 연결되는거라면 이 것은 온프레미스와 온프레미스 사이 연결을 AWS가 중간에서 해주는 것
	- AWS Site to Site VPN
		- 온프레미스와 AWS를 인터넷 기반 암호화 터널(IPSec)로 연결하는 서비스
		- Direct Connect보다 저렴하지만 안정성은 낮음
- Edge Networking & Content Delivery
	- Amazon CloudFront
		- AWS가 제공하는 CDN(Content Delivery Network)서비스 
	- AWS Global Accelerator
		- 전 세계 사용자의 트래픽을 AWS 의 백본 네트워크를 통해 가까운 리전에 보내주는 서비스
		- 핵심 기능
			- 어디서라도 빠른 접속 속도를 보장
				- 접속한 곳에서 가장 가까운 리전으로 신호를 전달
			- 장애 자동 감지 + 자동 장애 조치
				- Global Accelerator는 엔드포인트(리전 내 ALB/EC2 등)의 상태를 지속적으로 확인하여 문제가 발생한 리전이 있으면 정상 상태의 리전으로 즉시 우회(Route failover)
			- 고정 IP제공
				- Global Accelerator는 2개의 고정 IP를 제공하여 사용자가 이 아이피로 접속하고 AWS 내부에서만 리전별로 트래픽을 분리
			- 멀티 리전 활성-활성 아키텍처에 최적
	- AWS Route 53
		- AWS에서 제공하는 클라우드 기반 DNS 서비스
		- 주요 기능
			- Hosted Zone 관리
				- 도메인에 대한 DNS 레코드들의 그룹
			- Health Check 
			- Traffic Flow
- Application Networking
	- Elastic Load Balancing(ELB)
		- 사용자의 요청을 여러 서버에 자동으로 분산해주는 AWS 서비스
		- 목적
			- 트래픽을 여러 서버로 자동으로 나눔
			- 비정상 서버는 자동으로 제외(HealthaCheck)
			- Auto Scailing
			- 여러 가용 영역(AZ)로 분산해 실패에 대비
		- ELB 종류
			- Application Load Balancer(ALB)
				- HTTP/HTTPS(Layer 7)전용
				- 요청 내용 기반 라우팅 가능
				- 컨테이너(ECS/EKS)에 적합
				- WebSocket 지원
				- HTTPS 적용 가능
			- Network LoadBalancer(NLB)
				- TCP/UDP/QUIC 트래픽(Layer 4)
				- 금융 관련 시스템, 게임서버, IoT, 실시간 스트리밍 등에서 사용
			- Gateway Load Balancer(GWLB)
				- 서드파티 네트워크 보안 장비 배포(Layer 3)
				- 게이트웨이와 로드 밸런서의 기능이 결합
				- 트래픽이 보안 장비를 경유하도록 강제
				- 보안 장비에 대해서 스케일링 가능
	- Amazon VPC Lattice
		- 서비스 간 연결을 쉽게하기 위해 사용
		- AWS 가 관리해주는 서비스 메쉬(Service Mesh)
- Networking Security and Remote Access
	- AWS Verified Access
		- VPN 없이 사내 애플리케이션 접속 시 사용
		- Zero Trust 모델 기반
			- 제로 트러스트는 기본적으로 아무도 신뢰하지 않는다는 원칙 가짐
			- AWS Verified Access 는 사용자 ID, 디바이스 상태, 정책조건등을 조합하여 접근 여부를 결정
		- 구성 요소
			- Verified Access Instance
				- Zero Trust 평가를 수행하는 엔진
			- Verified Access Endpoint
				- 접근 제어를 걸어둔 대상 애플리케이션
			- Policy
				- JSON 기반 정책으로 누가 어떻 조건에 접근 가능한지 정의
			- Trust Provider
				- Id Provider
					- 사용자 신원 확인
				- Device Provider 
					- 디바이스 보안 상태 제공
