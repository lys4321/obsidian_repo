- Data Protection
	- AWS Backup
		- AWS 안에 있는 여러 서비스들의 데이터 백업을 중앙에서 관리하고 자동화 하는 서비스
		- AWS Backup 한 곳에서 정책을 정하고 전체 서비스에 적용하여 자동으로 수행하도록 한다.
		- 특징
			- 완전관리형
			- 정책 기반 자동화
			- 중앙 집중식 관리
			- 규정 준수에 도움
			- AWS Organizations와 통합
		- 지원하는 서비스
			- EC2, EBS, RDS, EFS, DynamoDB, FSx, Storage Gateway
	- AWS Elastic Disaster Recovery(EDR)
		- 장애 발생 시, 시스템 다운타임과 데이터 손실을 최소화하기 위한 DR 서비스
		- 서버의 데이터를 AWS 에 복제해두고 장애 발생 시, 바로 AWS 에서 시스템을 부팅해 서비스를 복구하는 서비스
		- 특징
			- 저렴하게 DR 구성
			- Pont-to-Time 복구 지원(특정 시점 복구)
			- DR 연습(드릴) 가능
			- 다양한 소스 서버 복제 가능
- Data Storage
	- Block
		- Amazon EBS(Amazon Elastic Block Store)
			- EC2 인스턴스와 사용하는 영구적인 블록 스토리지 서비스(HDD/SSD)
			- 특징
				- Persistent Storage(영구 스토리지)
					- EC2 인스턴스가 꺼져도 EBS 볼륨의 데이터는 유지
						- EBS 기반의 Root Volume 제외
				- Block Storage
					- 파일 단위가 아닌 블록 단위로 데이터를 저장하기 때문에 DB 같은 등에 적합
				- 가용 영역(AZ) 내 자동 복제
				- 짧은 지연 시간과 일관된 성능을 냄
					- 안정적인 IOPS를 제공
				- 용량 스케일링 가능
				- 프로비저닝한 용량 기준으로 비용 발생
	- File
		- Amazon FSx Family
			- Amazon FSx 는 특정 워크로드를 위해 고성능, 전문화된 파일 시스템을 AWS 에서 완전 관리형으로 제공하는 서비스 패밀리
			- 제품의 종류
				- Lustre
					- HPC, AI, 빅데이터용 병렬 고성능 파일 시스템
				- NetApp ONTAP
					- 엔터프라이즈급 NAS
				- OpenZFS
					- ZFS 기반 고성능, 스냅샵, 데이터 보호 기능
				- Windows File Server
					- Windows 파일 서버(AD, SMB, NTFS)
		- Amazon EFS(Amazon Elastic File System)
			- 확장 가능한 공유 파일 스토리지 서비스
			- EC2 인스턴스 들이 동시에 공유할 수 있는 NAS
			- 리눅스 기반의 워크로드를 위해 설계
			- 특징
				- 자동 확장(Elastic)
				- 공유 파일 시스템 (NFS 기반)
				- 고성능(High IOPS)
				- 고가용성 및 내구성
				- 온프레미스에서도 접근 가능
			- EFS의 스토리지 계층
				- EFS Standard
					- 자주 접근하는 활성 데이터용, 가장 빠름
				- EFS Infrequent Access(IA)
					- 가끔 접근하는 데이터
				- EFS Archive
					- 거의 접근 안하는 콜드 데이터
	- Object
		- Amazon S3(Amazon Simple Storage Service)
			- 객체 스토리지 서비스
				- bucket 이란 큰 공간에 객체를 저장하는 형태
					- 객체 = 파일 + 메타데이터
			- 특징
				- 강한 내구성
				- 큰 사이즈도 감당 가능
				- 자동으로 확장
				- 완전 관리형 서비스
				- 암호화 및 보안
					- 버전 관리가 가능
					- 서버측 암호화인 SSE 제공
					- IAM, 버킷 정책 등으로 세밀한 접근 제어 가능
					- 삭제 방지 기능도 제공(WORM)
				- 수명 주기 기능 지원
					- 오래된 데이터를 점차 저렴한 스토리지 클래스로 자동으로 이동시며 비용을 절감
- Data in Motion
	- AWS Storage Gateway
		- 온프레미스와 AWS 클라우드 스토리지를 연결해주는 하이브리드 스토리지 서비스
		- 스토리지 연결 방식
			- File Gateway
				- NFS, SMB 프로토콜로 파일 서버처럼 사용
				- 파일은 AWS S3에 저장
				- 로컬 캐시를 사용해 자주 쓰는 파일은 빠르게 접근이 가능
			- Volume Gateway
				- 온프레미스에서 ISCSI 블록 스토리지 형태로 사용
				- 종류
					- Store Volumes
						- 데이터 원본이 온프레미스에 저장
						- AWS에는 백업용의 스냅샷 저장
					- Cached Volumes 
						- 데이터 원본이 AWS (S3)
						- 자주 사용하는 데이터만 온프레미스에 캐시에 저장
			- Tape GateWay
				- 기존의 테이브 기반의 백업 장비(LTO) 를 그대로 사용하지만 실제 테이프는 AWS 의 가상 테이브인 VTL 임
				- AWS의 Glacier와 연동되어 비용이 매우 낮음
		- 작동 방식
			- 온프레미스에 물리 장비 형태의 게이트웨이를 설치
			- 애플리케이션은 기존처럼 NFS/SMB/ISCSI로 연결
			- 게이트웨이는 데이터를 로컬 캐시에 저장 시엔 접근을 빠르게 하며 AWS 에 저장할 땐 백그라운드에서 진행하게 한다
			- AWS 에서는 S3/EBS/Glacier 저장소에 보관
			- 네트워크가 끊겨도 로컬 캐시덕에 계속 동작
	- Amazon File Cache
		- 온프레미스와 여러 AWS 리전 곳곳에 흩어진 데이터를 고속의 단일 파일 시스템처럼 사용하게 하는 캐시 서비스
		- 기능
			- 여러 데이터 소스를 연결
			- 캐시 계층에서 초고속 액세스를 제공
			- 컴퓨팅 클러스터, EC2가 초고속으로 접근
		- 동작 원리
			- File Cache를 생성해 캐시가 AWS 에 배치 되게 함
			- 여러 데이터 소스를 연결
			- EC2, HPC, 컨테이너 애플리케이션은 파일 캐시를  파일 시스템으로 마운트
			- 파일 캐시가 요청 받은 파일을 제공
			- 필요 시 원본 데이터로부터 가져와 캐시에 저장
			- 컴퓨팅 작업에 고속 제공
