- 사용자가 컴퓨팅 활동을 위해 AWS에게 요청하는 할당 및 소비할 수 있는 측정가능한 컴퓨팅 파워
- AWS에서 사용한 만큼 비용을 청구한다는 개념과 연관됨
- AWS Computing 서비스의 종류
	- Amazon EC2 Services
		- Amazon EC2
			- Amazon Elastic Compute Cloud
			- 클라우드에서 안전하고 크기 조정 가능한 컴퓨팅 용량을 제공하는 웹 서비스
			- Amazon EC2는 새 서버 인스턴스(Amazon EC2 인스턴스)를 가져오고, 컴퓨팅 요구사항 변경 시, 용량을 변경함
			- Amazon EC2 인스턴스 타입(하드웨어에 해당)
				- 일반 CPU 기반 인스턴스(Graviton3 CPU)
					- C7g(Compute Optimized, 컴퓨팅 최적화)
						- CPU 연산 중심 작업에 효율적
							- HPC, 게임서버, 배치작업, CPU 기반 ML 추론
					- M7g(General Purpose, 범용)
						- 다양한 서비스 환경에서 가장 무난한 타입
							- 웹서버, 마이크로서비스, 게임서버, 캐시, 중간DB
					- R7g(Memory Optimized, 메모리 최적화)
						- 메모리 사용량이 많은 애플리케이션에 적합
							- Redis 같은 캐시서버, 대규모 DB, 빅데이터 분석 등
				- AI 특화 인스턴스 (전용 AI 칩 기반)
					- Inf2(Inferentia2기반 ML 추론 전용)
						- AWS Inferentia2 칩 사용
						- AI 모델을 학습한 뒤 실행하는데 최적화된 인스턴스
							- LLM, 이미지 모델, VIT, 대규모 AI 추론 서비스
					- Trn1(Trainium 기반 ML 훈련 전용)
						- AWS Trainium 칩 사용
						- GPU 대신 대규모 모델 '훈련'을 위한 저렴한 대안
							- LLM 학습, Diffusion 모델 학습
		- Amazon EC2 Auto Scaling
			- 애플리케이션의 가용성을 유지하도록 EC2 인스턴스를 자동으로 스케일링하는 서비스
			- 기능
				- 플릿관리(Fleet Management)
					- 인스턴스가 비정상 상태 시, 자동으로 교체해 정상으로 유지
				- 동적 조정(Dynamic Scailing)
					- 실시간 수요 변화에 따라 자동으로 스케일링
				- 예측 조정(Predictive Scailing)
					- 과거 데이터를 AI 모델이 분석하여 미래의 트래픽을 예상해 인스턴스 관리
		- Amazon EC2 Image Builder
			- 최신 보안 패치가 적용된 OS/컨테이너 이미지를 자동으로 빌드, 관리해주는 서비스
			- Image Builder 자체는 무료지만 이미지 생성 시, AWS 리소스 비용 부과
		- Amazon Lightsail
			- EC2보다 훨씬 단순한 VPS 서비스
			- 복잡한 AWS 설정 없이 서버 올리기가 가능
	- Serverless Compute
		- AWS Fargate
			- 컨테이너(ECS, EKS)를 서버에 대해 신경쓰지 않고 실행하게 하는 컴퓨팅 엔진
			- VM(EC2)를 프로비저닝하거나 클러스터잉을 관리할 필요가 없음
		- AWS Lambda
			- 서버없이 코드만 실행하는 서비스
			- 코드가 실행된 시간에 대해서만 비용을 지불
	- On-Promises and Edge Compute
		- AWS Local Zones
			- 일부 AWS 리소스를 대규모 인구 및 산업 센터와 가까운 곳에 배치하여 로컬 영역을 사용해 애플리케이션에 대한 짧은 지연 시간 액세스를 제공
			- 로컬 영역을 사용하는 이유
				- 엣지에서 지연 시간이 짧은 애플리케이션 실행
				- 하이브리드 클라우드 마이그레이션 간소화
				- 엄격한 데이터 레지던시 요구 사항 충족
		- AWS Dedicated Local Zones
			- AWS Local Zones에서 프라이빗한 환경 제공 기능이 추가된 것
		- AWS Outposts
			- 지연 시간이 적어야하는 워크로드, 규제 때문에 온프레미스에 두어야하는 경우 일 때 사용
			- 온프레미스에서 AWS 와 동일한 API, 도구, 하드웨어 사용
			- 종류
				- VMware Cloud on AWS Outputs
					- VMware ESXI 기반 워크로드 운영
				- AWS Native Outputs
					- AWS와 동일한 API 및 컨트롤 플레인
					- 온프레미스에서 Amazon EC2, EBS, ECS, EKS 등 사용
		- AWS Wavelength
			- 5G 모바일 엣지 컴퓨팅에 맞춰 설계된 AWS 인프라
			- 초저지연이 필요한 애플리케이션에 적합
			- 통신사 5G 네트워크 엣지에 AWS 인프라를 배치 해 트래픽 발생 시, 인터넷을 거치지 않고 Wavelength Zone 의 EC2/EBS로 전달하여 네트워크 지연 시간을 감소시킴
	- Cost Optimization
		- 요금제
			- 온디맨드(On-Demand)
				- 특징
					- 사용한 시간 / 초 만큼의 비용 지불
					- 선결제 방식이 아님
					- 인스턴스 on/off가 자유로움
				- 권장되는 상황
					- 테스트 및 개발 환경
					- EC2를 처음 사용 시
					- 트래픽 유동량이 급변하는 서비스일 때
			- 스팟(Spot)
				- 특징
					- 잉여 EC2 용량을 빌려쓰기 때문에 최대 90% 할인(온디맨드비교)된 가격인 요금제
						- 잉여 EC2 용량을 쓰기 때문에 AWS가 용량부족 시, 이 인스턴스를 회수하기 때문에  중단될 수 있음
					- 가장 싼 요금제
				- 권장되는 상황
					- 렌더링, 로그 분석, 빅데이터 등의 배치작업
					- 불시에 중단이 되어도 상관없는 시스템
					- 비용을 줄이고 싶을 때
			- 예약(Reserved Instance, RI)
				- 특징
					- EC2 인스턴스를 연단위로 약정해 사용하는 요금제
						- 온디맨드 대비 72%까지 할인
					- 지정한 인스턴스, 패밀리, 리전, OS, 테넌시를 고정적으로 사용해야함
					- 변경이 거의 불가(Standard RI)하지만 약간의 전환은 가능
				- 권장되는 상황
					- 트래픽이 일정한 서비스를 운영 시
					- EC2를 계속 가동하는 서버(웹, 데이터베이스 서버)
			- Savings Plans
				- 특징
					- 인스턴스에 묶이지 않고 사용 금액을 약정해서 할인 받는 방식의 요금제
						- 시간당 금액지불을 하겠다라는 금액기준
					- 인스턴스가 고정적으로 묶이지 않음
					- EC2. Lambda, Fargate 모두 자동 할인
					- RI 보다 유연하지만 약간 더 비쌈
				- 권장되는 상황
					- 여러 종류의 인스턴스를 사용해야할 때
					- 서버스펙 변동이 잦을 때
				- 종류
					- Compute Savings Plans
					- EC2 Instance Savings Plans
			- Dedicated Host(전용 호스트)
				- 특징
					- 물리 서버 1대를 독점해서 사용하는 요금제
						- 하나의 물리서버에 고객 인스턴스만 올라감
					- 규정 준수(컴플라이언스) 목적
					- BYOL 가능
					- 다른 고객과 공유하는 방식이 아님
					- 가장 비싼 요금제
				- 권장되는 상황
					- 보안, 규정 준수가 중요할 때
					- 기존의 온프레미스 라이선스를 재사용해야 할 때
		- AWS Compute Optimizer
			- AWS 의 관리형 서비스로 실제로 사용한 성능/매트리글 학습하여 리소스가 제대로 프로비저닝 되었는지 판단하고 변경점을 제시
				- 권장 안에는 예상 비용/성능 및 신뢰도가 포함
			- 지원하는 리소스(2025년 기준)
				- Amazon EC2 인스턴스
				- Amazon EC2 Auto Scailing 그룹
				- Amazon EBS 볼륨
				- Amazon Lambda 함수
				- Amazon ECS on Fargate 서비스
