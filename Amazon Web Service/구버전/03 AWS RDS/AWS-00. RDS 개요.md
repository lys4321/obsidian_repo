- AWS Cloud에서 관계형 DB를 더 쉽게 설치 운영 및 확장할 수 있는 웹 서비스
- 장점
	- 이미 사용중이던 DB 엔진을 그대로 사용가능
	- 백업 및  SW 패치, 장애 감지 및 복구를 관리
	- 백업을 생성하여 복구에 사용이 가능
	- IAM을 사용하여 권한을 정의해 액세스를 제어하거나 DB를 VPC에 배치하여 DB를 보호할 수 있다.
- EC2 및 온프레미스 배포와의 책임 비교
	- 온프레미스
		- 사용자가 서버의 하드웨어, OS, DB SW를 모두 관리해야 한다.
	- EC2
		- 서버의 하드웨어 부분 관리에 대한 부담을 줄임
		- EC2에서 DB를 실행하면 사용자 오류가 발생하기 쉽워 사용자가 관리를 잘 해야함
- RDS DB 인스턴스
	- DB 인스턴스는 AWS 클라우드에 있는 격리된 DB 환경
	- RDS의 기본 빌딩 블록은 DB 인스턴스이며 DB 인스턴스에 사용자가 만든 DB가 하나 이상 포함될 수 있다.
- DB 인스턴스 스토리지
	- 범용(SSD)
		- 개발 및 테스트 환경에 적합
	- 프로비저닝된 IOPS(PIOPS)
		- 낮은 I/O 지연시간과 일관된 I/O 처리량을 요구를 충족하도록 설계됨
		- 프로덕션 환경에 적합
	- Magnetic
		- 이전 버전과의 호환을 위해 지원
		- 
- RDS DB 인스턴스
	- 클라우드에서 실행하는 격리된 DB 환경이자 RDS의 기본 구성 요소
	- DB 인스턴스에는 여러 DB가 포함될 수 있음
	- DB 인스턴스마다 고객이 제공하는 고유 식별자가 있으며 AWS 한 리전 내 해당 고객에 대하여 고유해야함
		- DB 인스턴스 식별자는 RDS에서 인스턴스에 할당된 DNS 호스트 이름의 일부로 구성
	- 각 인스턴스는 DB 엔진을 지원
- DB 인스턴스 클래스
	- RDS DB 인스턴스의 컴퓨팅 및 메모리 용량을 결정
- RDS DB 인스턴스 스토리지
	- RDS의 DB 엔진에 대하여 EBS 볼륨을 사용하는 것
	- 스토리지 유형
		- 프로비저닝 된 IOPS SSD
			- 낮은 I/O 지연시간과 일관된 I/O 처리량 요구 충족을 위해 설계됨
			- 온라인 트랜잭션 프로세싱(OLAP) 워크로드에 적합
			- 유형
				- io2 Block Express 스토리지
				- io1 스토리지
		- 범용 SSD
			- 지연시간에 대해 민감하지 않은 개발 및 테스트 환경에 적합
			- 유형
				- gp3 스토리지
				- gp2 스토리지
		- 마그네틱
			- 역호환성(이전버전)을 위해 지원

- DB 파라미터 그룹
	- DB 파라미터 그룹은 하나 이상의 DB 인스턴스에 적용되는 엔진의 구성값에 대한 컨테이너 역할을 한다.
	- DB 엔진 및 DB 엔진 버전에 대한 기본 DB 파라미터 그룹은 DB 클러스터의 각 DB 인스턴스에 사용
	- DB 파라미터 그룹을 지정하지 않고 DB 인스턴스를 생성 시, 기본 DB 파라미터 그룹을 사용
	- 기본 DB 파라미터 그룹의 파라미터는 수정할 수 없기 때문에 필요하면 파라미터 그룹을 생성해서 사용
	- DB 인스턴스 파라미터는 정적이거나 동적
- DB 클러스터 파라미터 그룹
	- 다중 AZ DB 클러스터에만 적용
	- 다중 AZ DB 클러스터에서 DB 클러스터 파라미터 그룹의 설정은 클러스터의 모든 DB 인스턴스에 적용
	- DB 클러스터 파라미터 그룹을 지정하지 않고 다중 AZ 클러스터를 생성 시, 이 DB 클러스터는 기본 DB 클러스터 파라미터 그룹을 사용
	- DB 클러스터 파라미터는 정적이거나 동적
