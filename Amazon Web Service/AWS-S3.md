## **S3 이란?**
- 고유한 키-값을 사용해 원하는 수만큼 객체를 저장하는 객체 스토리지
- 데이터를 버킷 내에 객체, 계층적 데이터, 테이블 형식 데이터로 저장하는 객체 스토리지 서비스
- 객체는 버킷에 저장되며 각 객체의 크기는 5TB까지 가능
	- 버킷은 객체에 대한 컨테이너, 모음집이다.
- S3 > 버킷 > 객체
- 장점
	- 초기 용량 크기를 정하지 않아도 되는 확장성
	- 객체에 대한 강력한 일관성 및 내구성 제공
		- PUT, GET, DELETE, LIST 적용 범위를 가짐
		- 즉, 예를 들어 데이터를 생성하면 같은 리전 내 AZ들에게 데이터를 저장해 일관성을 유지
	- AZ 장애에도 같은 리전 내 AZ를 이용한 가용성
	- 버킷 정책으로 인한 보안 및 데이터 보호
	- 낮은 비용 대비 효율성
-----
## **S3의 기능**
- 다양한 사례에 맞는 스토리지 클래스를 제공
- 스토리지에 대한 관리 기능을 제공
- 버킷 및 객체에 대한 액세스 감사 및 관리 기능을 제공
- 데이터를 처리/변환하고 워크플로우를 트리거하여 다른 처리 작업을 자동화하는 기능을 제공
- 스토리지에 대한 로킹 및 모니터링 제공
- 스토리지 사용량에 대한 분석 및 인사이트기능 제공
-----
## **S3 매커니즘**
- 기본 동작
	1. 버킷을 생성 후
	2. 해당 버킷에 대한 이름 및 AWS 리전을 설정
	3. S3에서 객체로 해당 버킷에 데이터를 업로드
- S3은 버킷 내에, 여러 버전의 객체를 저장하여 복원 시, 사용
- 버킷과 버킷 내 객체는 private이며 액세스 권한을 명시적으로 부여해야만 액세스가 가능하다.
	- 액세스는
		- 버킷 정책
		- IAM 정책
		- ACL(액세스 제어 목록)
		- S3 액세스 포인트
		를 사용하여 관리

## **S3 스토리지 클래스**
- S3 Standard
	- STANDARD
	- 기본 스토리지 클래스
- S3 Express One Zone
	- EXPRESS_ONEZONE
	- 특별히 설계된 고성능 단일 영역 S3 클래스
		- 낮은 레이턴시를 지원해야할 시 추천되는 클래스
	- 해당 클래스 사용 시, 단일 AZ 내 여러 디바이스에 데이터가 중복으로 저장이 된다.
- Reduced Redundancy(비추천 됨)
- S3 Glacier 
	- 자주 엑세스하지 않는 장기 데이터를 저장하는 스토리지
	- 최소 저장 기간이 있음
	- 종류
		- S3 Glacier Instant Retrieval
			- 분기당 1회 액세스되며 검색 시간이 밀리초 단위일 경우 사용
			- 이미지 호스팅, 파일 공유 애플리케이션, 의료 정보 기록 애플리케이션 등 성능에 민감 시 적합
			- 최소 객체 크기는 128kb, 최소 저장 기간은 90일
		- S3 Glacier Flexible Retrieval
			- 1년에 1~2회 액세스되며 즉시 액세스 될 필요가 없는 아카이브 데이터일 경우 사용
			- 백업 및 재해 복구에 적합
			- 이 클래스에 저장된 객체는 아카이빙 되며 실시간 액세스에 사용할 수 없다.
			- 액세스 시, 복원 요청을 시작으로 요청이 완료되면 액세스가 가능한 객체의 임시 사본을 생성
				- 복원 시 사용하는 검색 계층
					- Expedited retrieval
					- Standard retrieval
					- Bulk retrieval
			- 최소 객체 저장 기간은 90일
		- S3 Glacier Deep Archive
			- 1년에 액세스 횟수 1회 미만일 경우
			- 저장된 객체는 아카이빙 되며 실시간 액세스가 불가
			- 액세스 시, 복원 요청을 시작으로 요청이 완료되면 액세스가 가능한 객체의 임시 사본을 생성
				- 복원 시 사용하는 검색 계층
					- Standard retrieval
					- Bulk retrieval
			- 최소 객체 저장 기간은 180일
			- 각 객체에 대하여 40kb의 추가적인 메타데이터가 필요
				- 32kb는 데이터 식별 및 검색에 필요한 메타데이터를 위한 용량
				- 8kb는 아카이빙 된 객체의 사용자 정의 이름 및 메타데이터 유지를 위한 용량

## **S3 구성요소** 및 기타 정보
- 버킷
	- 객체를 저장하는 컨테이너
	- 버킷의 공통 기능
		- S3 네임스페이스를 최상위 수준으로 구성
		- 스토리지 및 데이터 전송 요금을 담당하는 계정을 식별
		- 버킷을 사용량 보고를 위한 집계 단위로 사용
	- 유형
		- 범용 버킷
			- S3의 기본 버킷 유형이자 S3에 저장되는 객체의 컨테이너
			- 버킷과 S3 Express One Zone를 제외한 모든 스토리지 클래스에 원하는 수의 객체를 저장할 수있다.
				- 즉, 여러 AZ에 걸쳐 객체를 중복해서 저장이 가능
		- 디렉터리 버킷
			- 낮은 레이턴스 및 데이터 레지던시가 요구되는 상황에서 권장되는 버킷
			- 계층적 디렉터리 구조로 이루어짐
				- 접두사를 이용하여 계층구조를 설정
				- 접두사는 제한이 없음
			- 개별 디렉터리를 수평적 구조로 조정할 수 있음
		- 테이블 버킷
			- 일별 구매 트랜잭션, 스트리밍 센서 데이터, 광고 노출 같은 테이블 형식 데이터를 저장 시 권장
			- 쿼리 성능을 지속적으로 개선하고 테이블 스토리지 비용을 절감하도록 설계된 기능이 내장
			- 분석 및 기계 학습 워크로드에 적합한 S3 스토리지 제공
		- 벡터 버킷
			- 벡터를 저장하고 쿼리하기 위해 구축된 버킷
			- 전용 API 작업을 사용하여 벡터 데이터를 효율적으로 작성하고 쿼리
			- 기계 학습 모델의 벡터 임베딩을 저장하여 유사성 검색을 수행하거나 다른 AWS 서비스와 통합 할 수 있다.
- 객체
	- 객체의 요소
		- 키
			- 객체에 할당된 이름, 검색을 위해 사용된다
		- 값
			- 저장하는 컨텐츠
			- 임의의 바이트 시퀀스
		- 메타데이터
			- 객체 관련정보를 저장하기 위한 이름-값의 페어의 Set
			- 사용자 정의 메타데이터 설정 또한 가능
		- 버전 ID
			- 버킷 내에서 객체를 고유하게 하여 식별하기 위한 ID
			- S3이 생성하는 문자열
		- 하위 리소스
			- 객체에 관련된 추가 정보
			- 객체에 종속되며, 항상 객체/버킷 등의 다른 항목과 연결 됨
		- 액세스 제어 정보
			- 객체에 대한 엑세스 제어를 하기 위해 사용
		- 태그
			- 액세스 제어 및 비용 할당을 위해 저장된 객체를 분류
- Bucket policy
	- 버킷과 해당 버킷의 객체에 액세스 권한을 부여할 수 있는 RBAC기반 IAM 정책
	- 버킷의 소유자만 정책을 버킷에 연결이 가능
		- 권한은 버킷 소유자가 소유한 모든 버킷의 객체에 적용
		- 버킷 정책의 크기는 20kb로 제한
	- AWS에서 표준인 JSON 기반 액세스 정책 언어가 사용됨
- ACL
	- 권한이 부여된 사용자에게 개별 범용 버킷 및 객체에 대한 읽기 및 쓰기 권한을 부여하기 위한 데이터
	- ACL은 하위 리소스로써, 각 범용 버킷/객체마다 연결됨
	- ACL은 IAM보다 먼저 적용되는 액세스 제어 매커니즘
	- 현재는 비활성화가 기본으로 되어있으며 사용하지 않는게 추천
- Region
	- 버킷을 저장할 지리적 AWS 리전
