- 노드 란?
	- k8s에서 실제 애플리케이션이 실행되는 곳을 의미
	- 물리 서버, 가상머신 모두 가능
	- 하나의 클러스터에는 여러 노드가 존재 가능하며, 각 노드는 컨테이너화 된 애플리케이션(Pod)을 호스팅

- 노드의 구성 요소
	- kubelet
		- 노드에 항상 실행되는 에이전트
		- 기능
			- 노드에서 Pod가 정상적으로 실행하는지 감시
			- Pod 상태를 API 서버에 보고
			- Pod 스펙에 따라 컨테이너 런타임에 명령 전달
	- 컨테이너 런타임(Container Runtime)
		- 실제 컨테이너를 실행하는 엔진
		- 도커, containerd, CRI-O 등
		- kubelet 이 Pod 스펙을 바탕으로 컨테이너를 관리
	- kube-proxy
		- 네트워킹 및 서비스 라우팅 담당
		- 기능
			- Service IP를 Pod와 연결
			- 로드밸런싱 수행
			- 클러스터 내/외부 트래픽 관리

- 노드 역할 및 기능
	- Pod 실행 : 워커 노드는 컨트롤 플레인에서 스케줄된 Pod를 실행
	- 상태 보고 : kubelet이 Pod와 노드 상태를 API 서버에 주기적으로 보고
	- 네트워크 관리 : kebe-proxy를 통해 Service와 Pod 간 통신 제공
	- 리소스 관리 : 리소스 모니터링 및 컨테이너 할당

- 노드의 상태 종류
	- 주소
	- 컨디션
	- 용량
	- 정보

- 노드 Heartbeat
	- 클러스터가 개별 노드가 가용한지 판단하거나 조치를 취하는데 도움을 주는 데이터
	- 종류
		- 노드의 .state 에 대한 업데이트
		- kube-node-lease 내의 Lease 오브젝트

- 노드 컨트롤러(Node Controller)
	- 노드 등록 시점에 노드에 CIDR 블럭 할당
	- 노드버전을 최신으로 관리
	- 노드 동작을 감시
		- 노드가 접근불가(unreached) 상태일시, 노드의 .status필드의 Ready 컨디션을 Unknown으로 업데이트
		- 노드가 계속 불가능일시, API를 이용해 축출되도록 유도
