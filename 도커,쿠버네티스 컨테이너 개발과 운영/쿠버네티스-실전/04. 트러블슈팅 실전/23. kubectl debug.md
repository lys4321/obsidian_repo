- k8s 리소스를 디버깅하기 위한 임시 컨테이너(Ephemeral Container)이나 Pod 복사본을 만드는 명령어
- 임시로 만든 것에서 입력한 문제를 설명
- 디버깅 방식
	- Ephemeral Container 추가 방식
		- 실행 중인 Pod에 임시 컨테이너 추가
			- TroubleShooting 기능이 포함된 컨테이너만 추가(Pod 재시작은 필요 없음)
			- 대신, 클러스터에서 EphemeralContainer 기능이 활성화 되어야함
	- Pod 복사본 방식
		- 원래 Pod를 복사하여 새로 생성
		- 이 Pod에서 명령이나 환경변수 등을 변경하면서 디버그
	- 노드 디버깅
		- 문제가 발생한 노드에 직접 들어가 컨테이너를 생성
		- host namespace 공유 및 node 파일시스템을 마운트
		- 도커데몬이나 시스템 로그, 네트워크 네임스페이스 문제 등을 직접 조사 시 사용
- kubectl debug \~\~~ \[옵션]
- \~\~~ 의 종류
	- POD
	- 타입명 이름
- 옵션의 종류
	- 컨테이너 실행 관련 시, 사용하는 옵션
		- --arguments-only
			- -- 뒤의 내용을 커맨드가 아닌 인수로 전달
			- ENTRYPOINT를 유지하고 인자만 전달하려 할 시 사용
		- --attach
			- 컨테이너 시작 후 자동으로 attach
		- --container
			- 생성할 디버그 컨테이너의 이름을 지정
		- --env
			- 디버그 컨테이너에 환경변수를 지정
		- --image
			- 디버그 컨테이너에 이미지를 지정
		- --image-pull-policy
			- 클러스터 서버 설정에 따르고 이걸 비울 시, 서버가 default 적용
			- Always, IfNotPresent, Never 중 하나를 사용
		- -i
		- -t
	- Pod 복사 관련 옵션(copy-to 모드에서만 동작)
		- --copy-to
			- 원본 Pod를 복사해 새로  생성
		- --replace
			- 복사본 생성 후, 원본 삭제
		- --same-node
			- 복사한 Pod를 원본과 같은 노드에 스케줄링하도록 강제
		- --set-image=Pod명=이미지명
			- 복사된 Pod의 컨테이너 이미지 변경
		- --share-proccesses
			- 프로세스 네임스페이스를 공유
			- 디버그 컨테이너에서 다른 컨테이너의 PID 를 조회가 가능
			- copy-to 모드에서만 적용
	- Ephemeral Container 관련 옵션
		- --target
			- 임시 컨테이너를 어느 컨테이너를 기준으로 붙일지 지정
		- --profile
			- 디버그 컨테이너의 보안 프로필 및 capabilities 설정
