쿠버네티스
- 컨테이너화 된 애플리케이션을 관리하는 요픈소스 플랫폼
- 컨테이너 오케스트레이션 도구
-----
특징
- 컨테이너 배포, 스케일링 자동화(Autoscaling)
	- 스케일링 자동화에는 
		- Horizontal Pod Autuscaler(HPA)
		- Vertical Pod Autoscaler(VPA)
		- Cluster Autoscaler 등 있음
- 노드 장애 시 스케줄링 재배치, CrashLoopBackoff 복구
- 서비스 디스커버리 및 로드 밸런싱
- 자동 롤링 업데이트 및 롤백, Blue-Green, 배포, Canary 배포
- 비밀정보(Secret) 관리와 구성(ConfigMap)을 관리
-----
핵심개념
- Cluster(클러스터) : 노드들을 묶는 논리적 단위
	- 마스터 노드 : 클러스터를 관리하고 명령을 내리는 노드
	- 워커 노드 : 실제 애플리케이션이 돌아가는 노드
- Node(노드) : 클러스터 내에서 각자의 역할을 가진 항목
	- 마스터노드는 클러스터 관리/명령을 내리고 워커노드는 실제 애플리케이션을 담당
	- 마스터 노드 주요 컴포넌트
		- etcd
		- cloud-controller-manager
			- Replication Controller
			- StatefulSet Controller
	- 노드 내부 주요 컴포넌트
		- kubelet : 쿠버네티스 에이전트, 컨테이너 관리
		- kube-proxy : 네트워크 트래픽 관리
		- 컨테이너 런타임 : Docker, contrainerd 등
- Pod(파드) : 쿠버네티스에서의 최소 배포 단위
	- 1개 이상의 컨테이너를 그룹화
	- 같은 파드 내 컨테이너는 같은 IP와 볼륨을 공유
	- Pod Lifecycle
		- Pending 
		- Running
		- Succeeded
		- Failed
		- CrashLoopBackoff
	- init Container
- DaemonSet
- StatefulSet
- Deployment(디플로이먼트) : 파드의 선언적인 부분을 관리하는 담당
	- 자동 롤링 업데이트 및 롤백 가능
- Service(서비스) : 파드에 접근할 수 있는 추상화된 네트워크 엔드포인트를 담당
	- 파드의 IP는 동적이므로 서비스가 정적인 것처럼 파드의 IP를 담당하여 파드 IP가 변경이 되어도 문제가 없도록 잡근점을 제공
	- 타입
		- Cluster IP(클러스터 내부)
		- Node Port(외부 접근 가능)
		- LoadBalancer(클라우드 LB 연결)
		- ExternalName
		- DNS 기반 접근?
	- 서비스 디스커버리 원리?
- Namespace(네임스페이스) : 클러스터 안에서 리소스 격리
	- 권한(RBAC) ?
	- 쿼터 관리(ResourceQuota)?
- Volume(볼륨) : 파드 내 데이터 영속화
	- 컨테이너나 파드는 종료 시 데이터가 사라지므로 이를 저장할 공간이 필요한다 볼륨이 이를 담당]
	- 종류
		- emptyDir
		- hostPath - PersistentVolume(PV)/PersistentVolumeClaim(PVC)??
		- ConfigMap/Secret??
	- 영속성, 공유가능??

기본 워크플로우
1. 애플리케이션 이미지를 Docker로 빌드
2. Deployment YAML을 작성
3. kubectl apply -f deployment.yaml로 배포
4. 쿠버네티스가 Pod생성 스케일링, 네트워크 스토리지 관리
